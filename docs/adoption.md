# Spectodo v0.2 stable 共通導入ガイド

ここでいう**新規導入**は「導入先リポジトリにSpectodoの正本がまだない状態」を指します。リポジトリ自体が空とは限りません。企画資料だけ、コードあり、READMEのみ、完全に空、いずれも想定します。採用言語は共通で **v0.2 stable**。対象ごとに選択しません。

## 新規導入の指定方法（そのままコピー）

導入先リポジトリを開いたCodexに渡してください。**細かい作業手順は共通Skill内**に置き、毎回長いプロンプトを作成しません。

~~~text
このリポジトリにSpectodo v0.2 stableを新規導入してください。
共通Skill：https://github.com/myokoym/spectodo/blob/main/.agents/skills/spectodo-kickoff/SKILL.md
これは外部配布元です。ローカル未配置でも取得し、共通Skillの新規導入手順で進めてください。
資料・コードがあれば内容を全面調査して必要な構造再編・詳細inventory・Codex用導線を整備し、検証してください。
資料がなければ要件を捏造せず、整備可能な基盤と未確定事項を報告してください。
すでにSpectodoがある場合は新規上書き・自動移行せず、状態と適切な次の処理を報告してください。
詳細実行計画は明示指定時のみ作成してください。
~~~

## 新規導入が想定する状態

| 導入先の状態 | 共通Skillによる処理 |
|---|---|
| ① 完全に空／Git初期化直後 | 取得・配置可能な共通基盤と最小限の入口を整える。要件や製品Versionを創作しない。根拠がない間、無効な空inventoryを作らず未完了を明示 |
| ② README・企画・調査・検討資料のみ | 資料を実際に分析・構造再編する。採用済み要件を抽出し、根拠付きinventoryを作る。未決定案は確定仕様にしない |
| ③ コード・テスト・設定が既にあるがSpectodo未導入 | コードと資料の証拠を突き合わせてinventory、進捗、導線を整える。コードがあることだけで検証完了とはしない |
| ④ 配布Skill・仕様だけが一部配置済み | 同一SHAの正規配布物と差分・ユーザー変更を照合して安全に修復。新規の重複inventoryを作らない |
| ⑤ v0.2 inventory導入済み | **新規ではない**。この依頼では再初期化せず現状を報告。再整備する場合は下記の再キックオフを使う |
| ⑥ v0.1 inventory導入済み | **新規ではない**。勝手にv0.2へ移行しない。移行する場合は下記の明示的な移行指示を使う |
| ⑦ 複数プロジェクト／monorepo | 独立管理する実在境界だけScope化。単なるフォルダ分割ではScopeを増やさない |
| ⑧ 未コミット変更・既存指示・取得障害あり | 既存変更と有効な指示を保護。衝突箇所・取得不能箇所のみ保留し、可能な非破壊的調査は続ける |

空に近い状態ではv0.2構文とvalidatorが要求するCategory・Requirementを**架空の文で埋めてはいけません**。有効な要件が存在してから正本SPECTODO.mdを確定し、初期化未完了を報告します。空リポジトリでも作業自体を全停止しません。

## 導入済みの場合だけ使う別の指示

通常の新規導入では次の手続きを自動実行しません。導入状況に応じて、必要な場合だけ明示します。

**既存v0.2の再キックオフ・資料再編**

> Spectodo共通キックオフSkillを使い、この導入済みリポジトリの資料構造とv0.2 inventoryを全域で再監査・再整備してください。既存ID・進捗・導入元SHAを維持し、欠落・重複を修正して検証してください。詳細実行計画は明示指定時のみ作成してください。

**既存v0.1から共通v0.2への明示的移行**

> Spectodo共通キックオフSkillと公式移行規程を使い、このリポジトリのv0.1をv0.2 stableへ監査付き移行してください。全件の対応表を作成し、既存のID・制約・進捗・参照・決定経緯を保持して検証してください。

## 詳細実行計画も必要な場合（任意オプション）

**新規導入または再キックオフの依頼文の末尾にのみ**次の一文を追加してください。既存の詳細計画がある場合は重複せず更新し、未完了の採用済みRequirementを一括対象にします。計画の作成は実装開始を意味しません。

> 追加オプション：未完了の採用済みRequirement全体について、依存順の作業単位にまとめた詳細実行計画を一括作成してください。検証・停止・復旧・再開手順を記載し、実装は開始しないでください。

詳細規則と作業実行用の日本語文は、明示的な利用時に配布する [詳細実行計画ガイド](optional-execution-plans.md) にあります。

## 配布元・再現性・役割分担

- 配布元：https://github.com/myokoym/spectodo
- キックオフSkill：[.agents/skills/spectodo-kickoff/SKILL.md](../.agents/skills/spectodo-kickoff/SKILL.md)
- 通常運用Skill：[.agents/skills/spectodo/SKILL.md](../.agents/skills/spectodo/SKILL.md)
- 正式仕様：[spec/language-v0.2.md](../spec/language-v0.2.md)
- 明示的移行規程：[docs/migration-v0.1-to-v0.2.md](migration-v0.1-to-v0.2.md)

初回は**外部**配布元mainのコミットSHAを取得し、必要なファイルを同一SHAで揃えます。取得したSHAを導入先AGENTS.md等へ記録し、その後の通常再実行では固定SHAを再利用します。更新は明示指示がある場合だけ行います。導入先にSkillがないことは正常で、ローカル探索だけで停止しません。

**共通Skillが実行手順の正本**です。対象の調査、資料の統合・分割・移動、要件・根拠・進捗、Scopeとrouting、検証・セルフレビュー、再実行時の冪等性、空の入力や部分導入の扱いまで共通Skillで管理します。日本語の短い依頼文へ長い手順を複製しません。外部取得手段が全て失敗した場合、取得URL・実エラーを報告し、Spectodo固有の書き込みはしません。非破壊的な確認だけ続けます。
